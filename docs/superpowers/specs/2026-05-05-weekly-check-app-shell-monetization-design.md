# 주간체크 앱 셸 및 수익화 설계

## 요약

현재 주간체크는 기능은 늘었지만 화면이 여러 카드와 설명으로 퍼져 보여 앱처럼 응집된 느낌이 약하다. 이번 설계의 목표는 구조를 `상단 베젤 + 단일 본체 + 하단 탭 + 최하단 광고 바`로 단순화해서 시각적 밀도를 낮추고, 동시에 `무료 + 유료 구독 + 배너 광고` 수익 구조를 제품 안에 자연스럽게 심는 것이다.

핵심 방향은 두 가지다.

1. 정보 배치를 다시 짜서 `하나의 앱`처럼 보이게 만든다.
2. 수익화 요소는 본문을 방해하지 않는 위치에만 배치한다.

## 제품 목표

이번 변경이 끝나면 사용자는 아래를 바로 느낄 수 있어야 한다.

- 홈을 열었을 때 앱 구조가 단순하고 한눈에 이해된다.
- `홈 / 진행 / 기록 / 코치`가 목적별로 분리되어 하나씩 보기 쉽다.
- 무료 사용자는 광고가 어디에 있는지 명확하게 알 수 있지만, 본문을 읽는 흐름은 끊기지 않는다.
- 유료 사용자는 광고가 제거되고 더 깊은 기능이 잠겨 있지 않다는 점을 이해할 수 있다.

## 현재 문제

- 왼쪽 목록, 본문 카드, 설명 문구가 동시에 보여서 시선이 분산된다.
- 홈 화면에 역할이 겹치는 정보가 많아 첫인상이 흐리다.
- 화면 간 이동 구조가 앱 탭보다 대시보드 메뉴에 가깝다.
- 수익 구조가 아직 제품 안에서 어떤 위치를 차지하는지 정해지지 않았다.

## 선택한 방향

세 가지 후보 중 `앱 셸형`을 선택한다.

1. `앱 셸형`
상단 베젤 아래에 하나의 큰 본체만 두고, 화면 이동은 하단 탭으로 처리한다. 각 화면은 핵심 블록 1개와 보조 블록 1개 수준으로 줄인다.

2. `대시보드 정돈형`
기존 구조를 유지한 채 카드 밀도만 줄인다.

3. `완전 화면 전환형`
탭마다 아예 별도 전체 화면처럼 구성한다.

선택 이유는 현재 문제의 중심이 `카드 스타일`보다 `구조의 분산`에 있기 때문이다. 앱 셸형은 화면을 하나의 제품 프레임 안에 묶어 가장 강하게 정리된 느낌을 만든다.

## 전체 구조

최종 앱 프레임은 아래 순서로 고정한다.

1. `상단 베젤`
2. `본문 앱 셸`
3. `하단 탭`
4. `최하단 광고 바`

본문만 탭에 따라 바뀌고, 바깥 프레임은 유지한다. 사용자는 언제든 같은 앱 안에 있다는 감각을 유지해야 한다.

## 상단 베젤

- 중앙 상단에 `주간체크` 베젤 버튼을 유지한다.
- 어느 화면에서든 누르면 `홈`으로 이동한다.
- 시각적으로는 앱의 브랜드와 복귀 동선을 동시에 맡는다.
- 헤더 내부에 별도 홈 버튼은 두지 않는다.

## 하단 탭

하단 탭은 4개만 둔다.

- `홈`
- `진행`
- `기록`
- `코치`

탭은 항상 보이며, 현재 화면은 강하게 활성 상태로 표현한다. 기존 왼쪽 네비게이션은 제거한다.

## 화면별 구성

### 1. 홈

홈은 `다시 열 이유`를 보여주는 화면이다. 정보는 최소화한다.

포함 요소:

- 큰 `연속 체크인` 수치
- `이번 주 상태` 한 줄
- `체크인 추가` 주 버튼
- `이번 주 코치 보기` 보조 버튼

제외 요소:

- 상세 그래프
- 긴 설명 문구
- 여러 개의 요약 카드

홈의 역할은 빠른 확인과 빠른 진입이다.

### 2. 진행

진행 화면은 숫자 흐름을 보는 화면이다.

포함 요소:

- 큰 추이 그래프 1개
- `목표까지 남은 차이` 요약 1개

진행 화면에는 그래프가 주인공이어야 하며, 나머지는 보조 정보로만 남긴다.

### 3. 기록

기록 화면은 데이터 관리 화면이다.

포함 요소:

- 체크인 목록
- 날짜, 체중, 골격근량, 체지방률, 키
- 선택 시 상세 보기
- 상세 안에서 수정 / 삭제

기록 화면은 표에 가까운 읽기 흐름을 가져야 하며, 상세 정보는 목록에 모두 펼치지 않는다.

### 4. 코치

코치 화면은 이번 주 행동 제안을 모아두는 화면이다.

포함 요소:

- `이번 주 한 줄 해석`
- `이번 주 해야 할 것` 2~3개
- 프리미엄 잠금 기능 예고

코치 화면은 현재 상태를 길게 설명하기보다, 행동 문장 위주로 구성한다.

## 수익 구조

주간체크의 첫 수익 모델은 `개인 유료 구독`이다.

### 무료 플랜

- 기본 체크인
- 홈 / 진행 / 기록 / 코치 4개 탭 사용
- 최하단 광고 바 노출

### 유료 플랜

- 광고 제거
- 코치 해석 강화
- 더 긴 기간 비교
- 리포트 / PDF export

첫 구현에서는 실제 결제를 붙이지 않는다. 대신 `유료 상태 on/off`를 앱 상태로 가정하고, 잠금 UI와 광고 제거 동작만 먼저 만든다.

## 광고 바 설계

광고는 본문을 방해하지 않기 위해 `최하단 고정 영역`에만 둔다.

구조:

- 본문 아래
- 하단 탭 아래
- 앱 최하단 전체 폭 광고 바

동작:

- 배너 광고 코드 여러 개를 등록할 수 있다.
- 일정 시간 간격으로 다음 광고 슬롯으로 자동 전환된다.
- 광고 코드가 비어 있거나 로드 실패하면 기본 `스폰서 / 추천 슬롯` 카드가 대신 보인다.
- 무료 상태에서는 광고를 보여주고, 유료 상태에서는 `Premium 활성화됨` 같은 조용한 상태 바로 교체한다.

제약:

- 광고는 본문 중간에 끼워 넣지 않는다.
- 광고가 화면의 주인공처럼 보이면 안 된다.

## 프리미엄 진입점

프리미엄 유도는 과하게 크게 두지 않는다. 필요한 순간에만 보여준다.

후보 위치:

- 코치 화면 하단
- 진행 화면의 기간 비교 근처
- 리포트 export 버튼 자리

노출 방식:

- 잠금 아이콘
- 짧은 설명
- `Premium 보기` 버튼

## 상태와 데이터

현재 앱의 로컬 저장 구조를 유지한다.

- 체크인 데이터는 계속 localStorage 기반으로 저장한다.
- 목표 데이터도 기존 구조를 유지한다.
- 여기에 `isPremium` 같은 가벼운 UI 상태를 추가할 수 있다.
- 광고 코드는 우선 정적 설정 또는 상수 배열로 시작한다.

이번 단계에서는 로그인, 서버 저장, 사용자별 결제 상태 동기화는 하지 않는다.

## 포함 범위

- 앱 셸형 레이아웃 재구성
- 좌측 네비게이션 제거
- 하단 탭 네비게이션 추가
- 홈 / 진행 / 기록 / 코치 화면 단순화
- 최하단 광고 바 추가
- 광고 자동 전환 로직 추가
- 프리미엄 상태에 따른 광고 숨김 처리
- 프리미엄 잠금 UI 추가

## 제외 범위

- 실제 결제 연동
- 로그인
- 서버 저장
- 실제 광고 네트워크 승인 및 수익 정산
- 외부 광고 성과 측정
- 관리자 광고 관리 화면

## 오류 처리와 예외 상황

### 광고 코드가 비어 있을 때

- 빈 영역을 보여주지 않는다.
- 기본 스폰서 카드 또는 추천 슬롯으로 대체한다.

### 광고 코드 로드가 실패할 때

- 앱 본문 레이아웃을 깨지 않는다.
- 실패한 슬롯은 즉시 기본 카드로 대체한다.

### 체크인 데이터가 없을 때

- 홈은 `아직 시작 전` 상태를 보여준다.
- 진행 / 기록 / 코치는 각각 비어 있는 이유가 분명한 상태 문구를 보여준다.

### 유료 상태일 때

- 광고 바는 광고 대신 짧은 프리미엄 상태 바로 바뀐다.
- 잠금 기능은 해제된 상태로 보인다.

## 테스트 관점

- 하단 탭 전환이 안정적으로 동작하는지
- 베젤 버튼이 어느 화면에서든 홈으로 이동시키는지
- 홈 화면이 이전보다 명확하게 단순해졌는지
- 무료 상태에서 광고 바가 자동 전환되는지
- 유료 상태에서 광고가 숨겨지고 프리미엄 상태 바가 보이는지
- 광고 코드 실패 시 기본 카드로 안전하게 대체되는지
- 기록 상세, 수정, 삭제 흐름이 새 앱 셸 안에서도 유지되는지

## 성공 기준

- 사용자가 첫 화면을 보고 `앱처럼 정리됐다`고 느낀다.
- 홈에서 무엇을 먼저 해야 하는지 즉시 이해된다.
- 본문을 읽을 때 광고가 거슬리지 않는다.
- 프리미엄의 가치가 기능 차이로 자연스럽게 드러난다.
